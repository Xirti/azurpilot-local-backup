# 本地修复与固定启动入口

本目录保存 2026-10-09 核实后的本地修复状态。针对已复现的跨海域 45 秒误报恢复计时清理；截图链路异常仍需真实游戏验证。

## 日常使用

从安装目录双击 `启动WebUI_无限等待.cmd`。它直接使用现有 Python 环境启动 WebUI，并在启动前核对 Git 版本、两个修复模块的 SHA256 和部署设置。

固定期间，WebUI 的“启用内置更新和重载”关闭，“定时重启时间”留空。后台仍可能检查更新、展示版本提示；当前关闭重载的运行模式拒绝执行更新。不要使用会重新安装或更新程序的其他入口。

慢启动没有总等待时限。后端退出、端口冲突、前端页面不可用会明确停止并给出日志位置；再次运行会复用已就绪服务。已有 WebUI 不会自动加载刚修改的 Python 源码，需要先退出再重新启动。

命令行辅助检查：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start-webui-no-timeout.ps1 -CheckOnly
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start-webui-no-timeout.ps1 -NoBrowser
```

新启动日志在 `log/local-launch-*.txt`，就绪记录在 `cache/local-repair-startup.json`。Windows 虚拟环境的解释器入口可能转交给另一个 Python 进程，所以就绪记录的启动 PID 与实际监听 PID可以不同。

## 关闭后台

双击安装目录的 `关闭WebUI.cmd`。它核实本次服务身份后请求正常退出，停止 AzurPilot 任务、OCR、远程访问和共享辅助后台，保留浏览器、游戏与 MuMu。退出期间请勿启动新任务；网页断开连接属于预期现象。再次双击会提示已经关闭。重新使用 `启动WebUI_无限等待.cmd` 可恢复 WebUI。

关闭文件不按名字批量杀 Python、不调用任务停止按钮配置的收尾动作，也不修改任务启用状态或计时补丁。若退出超时会报告未完成，不强杀其他进程。旧版服务未带本地关闭通道，需要用新版启动入口重新启动一次。辅助检查：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\stop-webui.ps1 -CheckOnly`。

## 修复丢失或计划升级

`manifest.json` 固定了已验证的版本和源码内容。它不是自动补丁工具：发现版本变化或源码不一致时，只提示并拒绝启动，不会覆盖新版文件。不要通过重新计算哈希来绕过提示。

保留安装目录之外的修复包。若版本仍一致，可先检查补丁是否能干净应用，再恢复计时修改并运行针对性测试；版本已变化时，先对新版重新确认问题和补丁适用性。通过验证后才重新生成清单。恢复时使用最小差异补丁，不用旧整文件覆盖新版。

允许升级时，应先退出 WebUI、保存本地修改，再正常更新并核查新版本是否已包含修复。重新验证启动入口、计时测试与真实游戏流程后，再决定是否恢复内置更新。
